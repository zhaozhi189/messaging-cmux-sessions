# 可读收件箱门铃实施计划

目标：按用户确认的样式显示 `(from aimeter) [125604 契约核查] 请查 cmux 收件箱：完整编号`。

方案：默认提取正文首个非空行的短摘要，支持 `--summary` 指定简称；摘要仅作预览，仍按编号读取完整正文。采用现有 Python 协议入口生成并固定门铃，发送和补交共用它，不缩短编号、不改写旧消息、不自动读取正文引用的文件。复用目标终端宽度闸门，按显示列缩短摘要；首次生成后冻结文本，终端缩小时保守拒发。

## 实施与验收

- [x] `tests/test_routing.py`、`tests/test_delivery_wait.py`：先验证自动摘要、自定义简称、窄屏、旧消息、重试和草稿保护，确认新行为测试失败。
- [x] `scripts/protocol.py`：复用显示宽度计算，统一生成和读取门铃；新增记录固定摘要与通知文本，同编号禁止改摘要。
- [x] `scripts/send.sh`：支持 `--durable --summary`，按当前终端预算生成门铃；保留完整编号作为持久通知签名，dry-run 不落盘。
- [x] `scripts/delivery-wait.py`：精确匹配记录内的新门铃及旧门铃，补交仅发送回车。
- [x] 同步技能入口、README 和团队工作流；执行全量测试、语法、技能格式及 diff 检查；本轮不自动提交或推送。

## 重点检查

摘要含中文、路径、换行或控制字符时不产生终端指令；纯路径正文使用通用预览。相同摘要的不同消息按完整编号区分。窄屏和重复发送不得改变既有门铃。带草稿、忙碌或权限框时继续等待。旧信箱记录和已运行任务继续能按原编号读取与补交。

## 独立审查

独立审查发现并以隔离测试复现两处重要边界：摘要中的字面反斜杠可能被 cmux 解释为回车/Tab；以连字符开头的普通消息可能被宽度计算入口误解析成命令行选项。均先增加失败用例再修复：摘要的反斜杠全角可见化，并拒绝补交不安全旧通知；宽度参数加选项结束符并要求数值结果。原正文、旧门铃和安全等待规则保持原语义。单项回归通过后重新执行全量验证。

验证：全量 88 项本地测试及发送回归通过；Python/Bash 语法、技能格式与 `git diff --check` 通过。只生成通知预览，没有向真实协作会话注入测试消息。
